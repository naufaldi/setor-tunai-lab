# Release note v0.2.0

Draft untuk direview orang. Tanggal draft: 2026-10-20.

## Daftar perubahan

- **Added**: status `PENDING`/`REVERSED`, validator actor dan reason, tabel `deposit_events`; helper ledger `hasEntries` dan `postReversalEntries`; `markPending`, resolve, reverse; endpoint pending, resolve, reverse.
- **Changed**: guard `cancel` untuk setoran `PENDING`.
- **Fixed**: status `POSTED` dari `COUNTED`, retry dengan STAN sama tidak memposting ulang (INC-2026-1014-01); jaring pengaman reverse untuk ref ambigu.

## Risiko

| Risiko | Dampak | Mitigasi |
|---|---|---|
| Perubahan `src/deposit.service.ts` (alur POSTED, pending, resolve, reverse, guard cancel) | Uang/rekonsiliasi: salah transisi status dapat membuat setoran terposting ganda atau tidak terposting | Test status dan retry STAN sama; smoke test Rp 50.000 dan Rp 100.000 di staging; pantau journal 5 terminal |
| Perubahan `src/ledger.ts` (`postReversalEntries`) | Ledger: pembalikan salah menyebabkan debit/kredit tidak seimbang | Ledger tidak di-update/delete, hanya entri baru; test `ledger.reversal`; reverse idempoten (panggilan kedua tidak menulis); cek saldo seimbang saat rekonsiliasi |
| Perubahan `src/domain/deposit.ts` (status dan validator baru) | Uang: input actor/reason atau status tidak valid terlewat | Test `pending.domain` |
| Migrasi database: tabel baru `deposit_events` (`CREATE TABLE IF NOT EXISTS`, di `src/db.ts`) | Rekonsiliasi: riwayat aksi pending/reverse bergantung pada tabel ini; tidak mengubah tabel ledger | Ikuti `docs/prosedur-migrasi.md` (backup staging, catat durasi, skrip rollback, review dua orang) |
| Endpoint baru pending, resolve, reverse | Uang: reverse oleh pihak salah mengubah saldo rekening | Wajib `actor` dan `reason`, tercatat di `deposit_events` |

Tidak ada perubahan format pesan host pada commit yang ada.

## Langkah rollback

1. Redeploy artefak versi sebelumnya (v0.1.0).
2. Ledger tidak boleh di-update atau di-delete. Jika ada setoran yang sudah di-reverse atau di-resolve oleh v0.2.0, koreksi dilakukan lewat entri baru (reverse), bukan hapus.
3. Tabel `deposit_events` bersifat aditif; biarkan di database. Untuk migrasi, rujuk `docs/prosedur-migrasi.md` (skrip rollback).
4. Rekonsiliasi saldo dan setoran berstatus `PENDING`/`REVERSED` setelah rollback.
