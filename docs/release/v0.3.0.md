# Release note v0.3.0

Draft untuk direview orang. Tanggal draft: 2026-10-20.

Catatan: tag `v0.2.0` belum ada (v0.2.0 masih draft). Release ini hanya memuat perubahan setelah draft v0.2.0. Jika v0.3.0 dirilis tanpa v0.2.0 di-deploy lebih dulu, isi v0.2.0 (lihat `docs/release/v0.2.0.md`) ikut terbawa dan risikonya berlaku.

## Daftar perubahan

- **Changed**: hasil hitung (`count`) dengan lebih dari 20 lembar reject ditolak dengan error `TOO_MANY_REJECTS` (HTTP 400). Batas `MAX_REJECTED_PER_DEPOSIT = 20`; tepat 20 masih diterima.

## Risiko

| Risiko | Dampak | Mitigasi |
|---|---|---|
| Perubahan `src/domain/deposit.ts` dan `src/domain/money.ts` (validator `validateRejected`, konstanta batas reject) | Uang: setoran sah dengan reject > 20 lembar kini ditolak, nasabah harus mengulang setoran; salah batas (off-by-one) bisa menolak atau meloloskan setoran | Test batas di `test/deposit.test.ts` (tepat 20 diterima, 21 ditolak); smoke test di staging |
| Perubahan `src/deposit.service.ts` (validasi dipanggil di `count`) | Rekonsiliasi: validasi berjalan sebelum update, sehingga setoran yang ditolak tetap `OPEN` dan tidak menulis ledger | Test API di `test/api.test.ts` (HTTP 400); pantau journal terminal sampel |
| Perilaku response baru `TOO_MANY_REJECTS` | Klien/mesin CRM yang belum menangani kode ini mungkin menampilkan error umum | Koordinasi dengan tim Operasional ATM saat kirim jadwal deploy; pantau journal |

Tidak ada perubahan `src/ledger.ts`, migrasi database, atau format pesan host pada commit yang ada.

## Langkah rollback

1. Redeploy artefak versi sebelumnya (tag `v0.2.0` belum ada; gunakan artefak versi produksi terakhir yang berjalan).
2. Ledger tidak boleh di-update atau di-delete. Rilis ini tidak menulis entri ledger baru, tetapi jika ada koreksi data, lakukan lewat entri baru (reverse), bukan hapus.
3. Tidak ada migrasi database pada rilis ini, jadi tidak ada skrip rollback database (rujukan tetap `docs/prosedur-migrasi.md` bila nanti ada).
