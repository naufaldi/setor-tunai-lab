# Release note v0.3.0

Draft untuk direview orang. Tanggal draft: 2026-10-20.

Catatan: v0.2.0 masih berupa draft dan belum di-tag; v0.3.0 hanya memuat entri yang sebelumnya ada di Unreleased. Putuskan apakah v0.2.0 dirilis lebih dulu atau digabung dengan v0.3.0.

## Daftar perubahan

- **Added**: aturan reject. Hasil hitung dengan lebih dari 20 lembar reject per setoran ditolak (`TOO_MANY_REJECTS`); nilai reject yang bukan bilangan bulat >= 0 ditolak (`INVALID_REJECTED`).
- Commit `feat(plugin)`, `chore(plugin)`, `feat(skill)`, dan `docs` dilewati karena hanya tooling dan dokumentasi.

## Risiko

| Risiko | Dampak | Mitigasi |
|---|---|---|
| Perubahan `src/domain/deposit.ts` dan `src/domain/money.ts` (`validateRejected`, batas 20 lembar reject) | Uang/rekonsiliasi: setoran dengan reject > 20 lembar kini ditolak. Jika mesin CRM melaporkan reject lebih banyak, setoran gagal di sisi API sehingga bisa terjadi selisih antara fisik di mesin dan ledger | Test di `test/deposit.test.ts` dan `test/api.test.ts`; smoke test staging; pantau journal 5 terminal untuk `TOO_MANY_REJECTS`; konfirmasi batas 20 dengan Operasional ATM |
| Perubahan `src/deposit.service.ts` (`validateRejected` dipanggil saat hitung) | Uang: validasi dijalankan sebelum UPDATE, sehingga setoran yang ditolak tetap `OPEN` dan tidak masuk ledger | Test penolakan; tidak ada perubahan `src/ledger.ts` |

Tidak ada migrasi database dan tidak ada perubahan format pesan host pada commit yang ada. Response code baru `TOO_MANY_REJECTS` dan `INVALID_REJECTED` perlu dicek terhadap `docs/format-pesan-host.md` sebelum rilis.

## Langkah rollback

1. Redeploy artefak versi sebelumnya.
2. Ledger tidak boleh di-update atau di-delete. Jika ada setoran yang salah akibat versi ini, koreksi lewat entri baru (reverse), bukan hapus.
3. Rilis ini tidak punya migrasi database sendiri. Jika dirilis bersama v0.2.0 (tabel `deposit_events`), rujuk `docs/prosedur-migrasi.md`.
4. Rekonsiliasi setoran yang tertolak karena batas reject selama versi ini aktif.
